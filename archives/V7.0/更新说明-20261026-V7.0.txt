FlyLog V7.0 更新说明（内容组织层：无限级分类 + 标签 + 单页）
发布日期：2026-10-26
包名：FlyLog-V7.0.zip

【版本定位】
V6.x 这几轮一直在补安全与后台体验：V5.5 做安全加固，V6.0 修了四路审计
扫出来的 P0/P1，V6.5 重做了登录页。安全感是够了，但内容组织能力还停在
V1.0 的水平——分类只是文章表里一个字符串字段，没有层级、没有描述、
没有独立地址；文章之间除了分类之外没有任何横向关联手段。

V7.0 补的就是这块地基，一口气上了三件套：

    一、无限级分类（分类树，父子层级 + 面包屑）
    二、标签系统（多标签、标签页、标签云）
    三、单页 Page（关于我 / 友链这类不属于时间流的独立页面）

这一版最重要的设计约束是「老站零手工改库」：从 V1.0 到 V6.5 的任何一个
老站点，把文件覆盖上去、刷新一下首页，分类表、标签表、单页表会自动建好，
老文章里那个字符串分类会自动搬进新的分类树，并且老的 /?cat=分类名 链接
一字不改继续可用。整个搬迁过程幂等、可分次完成、失败只记日志不致命。

【一、无限级分类】
一、分类从「字符串」升级为「树」。新增 categories 表，字段包含
    name / slug / parent_id / sort_order / description。parent_id 指向
    父分类，0 表示顶级，层级数量不限——想搭「教程 > 无人机 > Mini 4 Pro」
    这种三层结构直接建就行。
二、后台 admin/categories.php。一个页面完成增删改查：新增分类时父分类
    用下拉选择（选项带缩进前缀，层级一眼看清），可填 slug 别名（留空
    自动按名称生成并保证唯一）、排序值、分类描述；编辑时会自动排除
    自己和自己的所有后代作为父级选项，杜绝把分类挂成环。
三、删除是安全的。删分类不会删文章：文章会被置成「未分类」，
    子分类自动上提一级到祖父节点下，不会因为删了父节点就丢一片内容。
四、前台行为。分类页地址形如 /?cid=8，命中父分类时把它所有后代分类的
    文章一起列出来（查「教程」能看到「无人机」和「Mini 4 Pro」下的
    内容）。侧栏分类目录按树形缩进展示，计数同样含子分类。
五、面包屑按祖先链展开：首页 / 教程 / 无人机 / 文章标题，每一级都能
    点回去。文章详情页也会自动插入所属分类的完整链路。
六、一键导入历史分类。后台分类页在分类表为空时会给出「从历史文章导入
    分类」按钮，把老文章里出现过的所有分类名一次性建成正式分类。
七、分类描述用于 SEO：填了之后该分类页的 description 就用它，没填才
    回落到站点描述。

【二、标签系统】
一、文章支持多标签。新增 tags 表与 post_tags 关联表，一篇文章可以挂
    任意多个标签，上限 20 个，单个标签不超过 50 字。
二、写文章时随手造词。后台编辑器新增「标签」输入框，逗号、空格、顿号
    都能分隔；保存时对已存在的标签直接复用、不存在的自动创建，不需要
    先去标签管理页建好再来用。留空提交即清空该文章的所有标签。
三、标签页与标签云。前台新增 ?tag=别名 归档页（标题、面包屑、
    description 都做了对应处理）；侧栏新增标签云，字号按使用频率分
    五档，越常用的标签越大越显眼。
四、后台 admin/tags.php。可改名、改 slug、删除、清理空标签。删除标签
    只解除与文章的关联，文章本身不受影响。
五、文章详情页底部展示标签芯片，点击直达标签归档页。

【三、单页 Page】
一、新增 pages 表与前台 page.php。单页适合放「关于我」「友情链接」
    「友链申请」「打赏」这类不属于博客时间流的内容。
二、区别于文章：单页不进首页列表、不进 RSS、不进归档、没有留言板，
    但它有自己的标题、slug、正文、排序、发布/草稿状态，并且同样支持
    自动生成目录（TOC）。
三、后台 admin/pages.php 管理增删改；草稿状态的前台访问会返回 404，
    不会出现「半成品页面被搜到」的情况。
四、想让单页出现在导航里：去「导航菜单」加一条链接 page.php?slug=别名
    即可（前台导航本来就是自定义菜单，无需改模板）。

【四、老库升级路径（重点）】
一、补表：system/db.php 的 fly_db_migrate() 里增加了「缺表则建」，
    每个请求进来都会检查 categories / tags / post_tags / pages 四张表
    在不在，不在就按当前数据库方言（MySQL / MariaDB / PgSQL / SQLite）
    建出来。SQLite 与 PgSQL 的主键、唯一键写法差异已在建表函数里处理。
二、补列：posts 表增加 category_id 列，同样是「缺列则加」。
三、搬数据：新增 fly_db_migrate_v7()，把老文章里 category 字符串
    建成分类记录并回填 category_id。刻意做了三点保护——
      · 幂等：只处理 category_id 还是 0 的行，重复执行无副作用；
      · 省流：每次请求最多搬 50 条，搬完自然停，不会拖慢正常访问；
      · 兼容：slug 直接沿用原分类名，所以老链接 /?cat=航拍 照旧可用。
四、双写兼容：后台保存文章时会把分类名同时写回旧的 category 字段，
    老模板、老插件、导出的旧数据都还能正常拿到分类名，不会因为升级
    就集体失效。
五、前台兼容：万一分类树还是空的（极端情况），侧栏会自动回落成旧的
    「按字符串分组」统计，界面不会开天窗。

【五、SEO 与其它】
一、sitemap.php 顺手修了一个老毛病：此前输出的 loc 是相对路径
    （/post/1.html），不符合 sitemap 规范。现在统一拼成绝对地址，
    并把分类页、标签页、单页都纳入了 sitemap。
二、路由新增三种类型：catid（分类树）、tag（标签）、single（单页）。
    这三种一律走查询串形式，不依赖服务器的伪静态重写规则，换主机、
    换面板都能直接用，不需要去面板里加 rewrite。
三、分类树 / 标签 / 搜索这三类条件视图不再复用首页静态快照，避免
    静态模式下条件页串味。
四、删除文章时会连带清理它的标签关联，post_tags 不会留下孤儿行。

【七、升级方式】
    整份覆盖即可，config.php 不要覆盖（线上配置保持原样）。
    首次访问任意页面会自动完成建表、补列、搬迁三步，无需运行安装器。
    升级前建议备份一次数据库——虽然迁移是幂等且安全的，但备份是好习惯。
