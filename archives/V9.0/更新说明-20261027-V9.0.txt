========================================================
FlyLog V9.0 更新说明
发布日期：2026 年 10 月 27 日
版本定位：后台站长管理增强（Admin & Editorial Boost）
========================================================

一、版本定位
----------
V9.0 是 FlyLog 在 V8.5（前台阅读体验）之后转向「后台」的一次专项升级，
对应路线图中的**维度二·后台站长管理**。前几个版本我们把力气都花在读者看得见
的地方：主题外观、阅读体验、互动与统计。这一版反过来补站长的手感——让日常
运维中最啰嗦、最重复的几件事变得一次搞定。

本版共落地 6 项能力：内容批量操作、草稿预览、友情链接管理、SEO 字段可视化
编辑、媒体库缩略图，以及操作日志导出（在 V9.0 周期内先行完成）。

在设计上我们坚持了三条老规矩：
  1) 老站升级零风险——新增结构全部走「缺表建表、缺列补列」的幂等迁移，
     已经在线上跑着的老库不用手工执行任何 SQL；
  2) 绝不因为附属功能拖垮整站——友情链接这类新表即使没建出来，相关函数
     也只是安静地返回空列表，站点照常运行；
  3) 四库无关——links 表的列名刻意避开了 SQL 保留字（用 description 而不是
     desc、sort_no 而不是 sort），MySQL / MariaDB / PostgreSQL / SQLite 四种
     数据库共用同一份建表语句，不需要为某个方言单独改写。

二、核心功能（维度二·后台站长管理）
--------------------------------
1. 内容批量操作（Bulk Actions）
   - 文章列表每一行的行首新增复选框，表头提供「全选 / 全不选」，
     并实时显示「已选 N 篇」，勾选状态一眼可见；
   - 支持 6 种批量动作：移入回收站、转为草稿、转为发布、设为置顶、
     取消置顶、批量移动到指定分类；
   - 每一篇都会单独写一条审计日志（带 bulk 前缀），事后能精确追查
     「谁在什么时候批量动了哪些文章」，不会因为批量操作留下审计盲区；
   - 单次最多处理 200 篇，既满足真实使用场景，也防止一次误操作把请求拖垮；
   - 移动分类时会同步回写老的分类名字段，保证老模板、导出数据、插件
     拿到的分类名依然一致。

   实现上有个细节值得一提：文章列表里每一行原本已经有两个独立的小表单
   （置顶、删除），而 HTML 规范不允许表单嵌套。我们没有大改结构，而是把批量
   表单放在表格外面，再用 HTML5 的 form 属性把行内复选框「远程挂靠」到这个
   表单上，既没有嵌套，也不用把行内按钮改成脚本提交。

2. 草稿预览（Draft Preview）
   - 以前草稿只能靠脑补：前台不让看，后台也看不到真实排版。现在编辑页
     新增「👁 预览（草稿也能看）」按钮，点开就是前台真实效果；
   - 两种放行方式：后台已登录时直接可见（最常用）；或者用一条带令牌的
     预览链接把草稿发给别人临时看一眼；
   - 预览令牌 = 文章 ID + 过期时间戳 + HMAC 签名，签名密钥首次生成后存进
     options 表长期复用，令牌本身不入库、无状态可校验，**12 小时后自动作废**；
   - 令牌与文章绑定：拿 A 文章的令牌去看 B 文章是无效的，防止一条链接
     被拿去遍历全站草稿；
   - 预览页自动标记 robots: noindex,nofollow，并在正文顶部显示醒目提示条，
     说明「普通访客访问会显示文章不存在」，避免误把未定稿内容当正式内容；
   - 安全底线不变：未登录、无令牌的访客访问草稿依旧是 404，一条泄露路径
     都没有新增。

3. 友情链接管理（Blogroll）
   - 新增 links 表与后台「友情链接」页面，支持新增、编辑、删除、隐藏/显示、
     排序号调整，还能给每个站配一个 Logo 图标地址；
   - 前台侧边栏自动渲染「🔗 友情链接」一栏，按排序号升序排列；没有填 Logo
     时用站点名首字生成一个彩色圆标，视觉上不空；
   - 一条链接都没加时整块侧栏不渲染，不会在页面上留一个空标题；
   - **URL 安全**：只放行 http / https，javascript:、data:、vbscript: 这类
     伪协议在入库前就被拒绝。这一点很关键——后台存进去、前台渲染成
     <a href="javascript:..."> 就是典型的存储型 XSS；
   - 前台输出的链接统一带 rel="nofollow noopener"，既符合 SEO 惯例，
     也堵住 window.opener 反向Tab劫持。

4. SEO 字段可视化编辑（SEO Editor）
   - 编辑文章时新增「🔍 SEO 设置」折叠面板，三个字段：SEO 标题、关键词、
     SEO 描述，全部选填；
   - 面板底部有一块**搜索结果模拟预览**，随输入实时更新，站长填的时候就能
     看到将来在搜索结果里大概长什么样；
   - 字数统计带建议阈值（标题 ≤ 60、描述 ≤ 160），超出时数字变红提醒；
   - 留空即回落：不填就用「文章标题 - 站点名」和自动截取的正文摘要，
     所以**老文章一个字不改也完全不受影响**；
   - 前台会优先使用 SEO 字段输出 <title>、meta description、meta keywords。

   顺带修掉一个隐蔽的小问题：以前文章页组装标题时先转义一次、模板输出时
   又转义一次，标题里出现引号或 & 时会被双重转义显示成 &amp; 这类怪字符。
   现在统一由模板出口做一次转义，源头不再重复处理。

5. 媒体库缩略图（Media Thumbnails）
   - 附件（媒体库）列表新增「预览」列：图片直接显示缩略图，
     非图片按类型给出图标（🖼 图片 / 🎬 视频 / 🎵 音频 / 📕 PDF / 🗜 压缩包 /
     📄 文档 / 📊 表格 / 📽 演示），一眼能分清文件类型；
   - 缩略图由浏览器直接缩放显示，**不依赖 GD 图形库**。这一点是刻意的：
     部分虚拟主机把图像处理相关的函数也一并禁用了，服务端生成缩略图
     反而会成为新的报错源；
   - 每行新增「复制链接」按钮，一键复制附件外链地址，粘贴到编辑器即可引用；
     浏览器不支持剪贴板 API 时自动降级为弹窗选中，不会点了没反应。

6. 操作日志导出（Audit Export）
   - 审计日志页新增「导出 CSV」按钮，按当前筛选条件导出操作记录；
   - 文件名带日期，字段包含时间、操作者、动作、对象类型、对象 ID、详情、IP；
   - CSV 转义按 RFC 4180 处理：字段含逗号、引号、换行时正确加引号并把内部
     引号翻倍，Excel 打开不会串列；
   - 导出前输出 UTF-8 BOM，避免 Excel 打开中文乱码。

三、数据结构变动
--------------
新增表（缺表才建，幂等）：
  links：id / name / url / description / logo / sort_no / visible / created_at

新增列（缺列才补，幂等）：
  posts.seo_title    VARCHAR(255)
  posts.seo_keywords VARCHAR(255)
  posts.seo_desc     VARCHAR(500)

以上变更全部由系统启动时自动执行的轻量迁移完成，站长无需手工干预。
老库升级后，SEO 三列默认为空字符串，行为与升级前完全一致。

四、兼容性与升级方式
------------------
- 支持 MySQL / MariaDB / PostgreSQL / SQLite 四种数据库，links 表在四种方言下
  共用同一份建表语句（SQLite 与 PostgreSQL 会自动剥离重复的表级主键声明）；
- 升级方式：增量覆盖本次改动的文件即可，不需要跑安装程序，不会动到
  已有的 config.php 与数据；
- 友情链接表若因权限问题没建出来，后台页面会明确提示「数据表尚未创建，
  请访问一次站点首页触发自动升级」，而不是甩一个空白页面；
- 无 mbstring 扩展的环境同样可用：涉及多字节截断的地方都做了降级处理。
